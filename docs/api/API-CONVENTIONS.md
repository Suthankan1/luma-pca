# REST API conventions and contract governance

- Prefix `/api/v1/` for domain routes; `/actuator/health/readiness` is operational.
- JSON uses ISO-8601 timestamps with `Z`/offset, stable UUID IDs, explicit status enums, cursor pagination for large datasets, consistent `ProblemDetail` errors.
- Roles and academy/course/batch scopes are server-enforced per route; path IDs are untrusted. No endpoint may return raw Zoom secrets.
- State-changing operations use authenticated BFF CSRF measures, request IDs and audit records. For critical mutators include idempotency keys.
- Never turn tentative architecture endpoints into documented deployed functionality until tests prove them.
- `contracts/openapi/platform-v1.yaml` lists exactly the endpoints the API serves (`scripts/check-openapi.py`, the `contract` CI workflow, fails on any difference); it is written by hand, not generated. Implemented: `GET /api/v1/system/status`, `POST /api/v1/auth/login`, `POST /api/v1/auth/activate`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, `POST /api/v1/auth/logout-all`, `GET /api/v1/auth/me`, `GET /.well-known/jwks.json`, and `GET`/`POST` on `/api/v1/courses` and `/api/v1/batches` with `GET`/`PUT` on `/{id}`. Updates send the `version` last read and get 409 if it is stale. A record in another academy returns 404, never 403. Small academy-bounded lists (courses, batches) are returned whole; cursor pagination applies to large datasets. Students (`/api/v1/students`, keyset-paginated by student number with `after` and `limit` up to 200), enrollments (`/api/v1/batches/{id}/enrollments`, `PUT /api/v1/enrollments/{id}`, `/api/v1/students/{id}/enrollments`) and own-record routes (`/api/v1/me/student`, `/api/v1/me/enrollments`) are implemented, as are staff administration (`GET`/`POST /api/v1/staff-accounts`, `GET /{id}`, `PUT /{id}/roles`, `POST /{id}/disable`) and invitations (`POST /api/v1/accounts/{id}/invitations`, returns the activation token once with `Cache-Control: no-store`), class sessions (`GET /api/v1/class-sessions?from&to[&batchId]` with a window of at most 92 days, `GET /{id}`, `GET /{id}/students`, `POST`, `PUT /{id}`) and staff assignments (`GET`/`POST /api/v1/batches/{id}/assignments`, `DELETE /api/v1/assignments/{id}`, `GET /api/v1/me/assignments`). Account administration/enrollment/batch/webinar/attendance routes are planned.
